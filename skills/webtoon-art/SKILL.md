# 캐릭터와 작화

기본 모델은 GPT Image 2.5, `quality: medium`(사람이 다른 걸 말하면 따른다). 그리기 전에 `generate_image` 의 `get_cost: true` 로 한 장 값을 확인하고(`generate_image_batch` 에서는 안 된다) `project.json` 의 `price_per_image` 에 적는다. 총액을 말한 뒤, `consent.md` 의 승인자에게 허락받는다. 이 스킬이 바로 불려도 승인과 상한을 건너뛰지 않는다. 모델과 품질을 바꾸면 값이 바뀌니 다시 알린다.

## 사진

- 본인이 "이 사람이 나야"라고 한 사람만 쓴다. 함께 찍힌 사람, 특히 아이는 잘라 낸다. 잘라도 남으면 외부로 보내지 않는다.
- 잘린 결과를 직접 본 뒤에 올린다. EXIF 가 빠지도록 png 로 바꾼다.
- 아이 캐릭터는 글 설명으로만 그려 실제 얼굴과 닮지 않게 한다.

## 캐릭터 시트

- 앞 · 옆 · 뒤 + 표정 4개, 3:2, 단색 배경.
- 주변 인물은 주인공과 확연히 다르게 적는다. 머리, 체형, 옷 색, 안경 없음. 이유: 참고 그림을 보내면 모두 주인공 얼굴로 나온다.
- 프롬프트에 특정 스튜디오 이름을 쓰지 않고 그림체를 말로 설명한다.

## 컷 프롬프트

- 바뀌는 것은 장면 · 구도 · 비울 자리뿐이다. 캐릭터 줄과 그림체 줄은 글자 하나 안 바꾸고 붙인다.
- 나오는 사람의 시트를 `medias: [{value: <작업 번호>, role: "image_references"}]` 로 보낸다.
- 끝에 `no text, no letters, no numbers, no speech bubbles` 를 넣는다.
- 말풍선 자리를 비우게 적는다. 콘티의 비율을 지킨다.
- 소품은 보는 사람 기준으로 적는다. 카메라를 주인공 어깨 너머에 두면 공책이 뒤집히지 않는다.
- 어두운 창 앞에 사람을 두지 않는다. 반사된 얼굴이 물리적으로 틀리게 나온다.

## 보내기

- 한 번에 2~4장씩. 한꺼번에 보내면 요청 한도에 걸린다.
- 실패한 컷만 다시 보낸다. 시간 초과면 결과를 확인하기 전에 다시 보내지 않는다.
- 내려받은 뒤 긴 변 1100px jpg 로 `art/` 에 둔다. 다시 그리는 컷은 이전 그림을 지우지 말고 `-before` 를 붙여 남긴다. 이유: 메이킹북의 전후 비교에 쓴다.

## 다 그리면

컷을 한 장씩 직접 본다.

| 볼 것 | 걸리면 |
|---|---|
| 글자, 간판, 번호 | 그 컷만 다시 |
| 얼굴이 시트와 다름 | 시트를 참고로 다시 |
| 인물이 복제됨 | 인물을 더 다르게 적어 다시 |
| 소품이 뒤집힘, 반사, 손가락 | 그 컷만 다시 |
| 비울 자리가 없음 | 식자에서 바깥 해설로 처리, 안 되면 다시 |

일부만 바꿀 때는 현재 그림을 참고로 보내고 "나머지는 그대로"라고 적는다.

## 기록

`project.json` 의 `image` · `width` · `height` · `status` 를 고치고, `credits` 에 실제로 쓴 값을 단계별로 더한다. 다시 그린 값도 빠짐없이 적는다.

## 테스트 시나리오

- 정상: 총액 허락 → 2~4장씩 그림 → 직접 확인 → 기록.
- 오류: 429 → 실패한 컷만 줄여서 다시 보낸다.
